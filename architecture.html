Architecture

One policy engine, two native platform implementations.

Flow

CLI configuration
  → bounded discovery and classification
  → typed eligibility / retention decisions
  → final metadata and process revalidation
  → explicitly authorized native removal
  → category counters and retained reasons

Discovery supplies facts; eligibility decides what may proceed. Actions own filesystem and repository effects. A scan is not an irrevocable deletion plan.

Native repository state

Current development uses gix and jj-lib for native repository facts. Bounded external Git/JJ commands remain where the workflow requires them. CLI and library versions both belong in the verification record.

Concurrency and accounting

Discovery and review use bounded queues and worker pools. Execution revalidates facts at effect boundaries. Counters separate physical workspaces and logical bytes from registrations and branch operations.

Performance claims require measurements for the workload in question. A faster scan is not a stronger atomicity or recoverability guarantee.
