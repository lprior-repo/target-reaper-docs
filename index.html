Target Reaper DevDocs

Build less clutter. Keep the work that matters.

Target Reaper finds stale Rust targets, generated artifacts and old Git/JJ workspaces. It separates discovery from authorization, starts with a preview, and checks filesystem and process activity again before deleting eligible data.

Your first run

target-reaper --root "$HOME/src" --age-days 7 --min-size 100M --list

Start with one projects directory. Read the classifications and retained reasons. Add --execute only after reviewing the exact scope and policy you selected.

Two native platforms

macOS and Linux share the cleanup policies. Native filesystem handles and process snapshots supply platform-specific evidence. GNU timeout and Git are required; JJ workspace cleanup additionally uses native jj.

See platforms and verification status before treating a build or historic test result as current runtime evidence.

Know the boundary

The default policy protects unfinished work. Broader deletion flags grant explicit authority. A preview can become stale, and execution is not atomic against hostile concurrent writers. Reported bytes are logical sizes, not physical free-space measurements.

Read the safety guide before automating a command.
