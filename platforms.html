Platforms and verification

Target Reaper supports native Linux and macOS. Other operating systems are rejected at compile time.

Packaging targets

OS / architecture Rust target Scope
Apple-silicon macOS aarch64-apple-darwin Primary Mac package
x86-64 Linux, glibc x86_64-unknown-linux-gnu Primary Linux package
Intel macOS x86_64-apple-darwin Source build; separate native verification required
Other Linux architectures Platform-specific target Source build; separate native verification required
Windows — Unsupported

Every archive identifies its exact target and commit. macOS and Linux binaries are not interchangeable; glibc and musl Linux targets are also distinct.

Native capability boundary

Capability macOS Linux
Process/file activity Native lsof snapshots Visible /proc process data
Mount boundaries Mount snapshots and filesystem identity Kernel/filesystem identity checks
Path traversal Descriptor-relative no-follow traversal openat2 resolution restrictions
External command bounds GNU timeout via coreutils GNU timeout via coreutils
Workspace authorization Shared policy, native Git/JJ integration Shared policy, native Git/JJ integration

Missing or incomplete required evidence retains candidates. These checks do not create an atomic lock against hostile concurrent writers.

Interpreting evidence

  • A native build proves compilation for its target and configuration.
  • A native fixture pass applies to its exact commit, test selection and environment.
  • Cross-compilation or Linux-target Clippy on a Mac is static evidence, not a Linux runtime pass.
  • Older commits' tests remain older-commit evidence until the new head is checked.
  • Empty check lists, interrupted runs and zero-test filters are not passing suites.

Current development snapshot

This documentation starts from main commit 8e73fe0. Its stable compiler pin exposed a nightly-only wrapper option. The focused compatibility fix supports stable builds while preserving the exact nightly/dev allowlist and rejecting bootstrap overrides.

The corrected snapshot passed 1,022 native macOS tests, zero skipped, on Apple silicon with Rust 1.99.1 and macOS 27.0.1. That run used the 8e73fe0 base plus the reviewed portability fixes. The first complete run had 999 passes and 21 failures; those failures and the resource-stopped build attempts remain preserved.

Corrections distinguish an empty test process index from unavailable visibility, use filesystem-portable raw-reference fixtures, and test native path limits explicitly. Production Mac activity checks remain fail closed. Debug symbols and incremental output were disabled for resource containment; runtime assertions and overflow behavior remained unchanged.

The initial strict native Clippy run stopped at a 1 GiB task-owned build-cache limit. Its approved 1.5 GiB continuation completed within the limits and reported 14 source errors, prompting the follow-up fixes. Neither failure is recorded as a pass; the earlier test evidence remains tied to its source snapshot.

Native macOS ARM64 and Linux x86-64 verification now uses explicitly authorized GitHub-hosted OS runners. The first hosted attempt failed before completing either suite; its receipts remain separate from successful runs. Consult PR #3 verification for the latest exact-head result. A skipped, failed or interrupted job is not a current-branch pass. The release guide describes the resource limits and development-artifact boundary.

OS support policy, packaging, and a particular native verification receipt are different facts. See development for the exact verification commands and release packaging for artifact provenance.
