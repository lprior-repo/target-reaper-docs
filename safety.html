Safety and authorization

Start with a narrow root and review a preview before enabling execution. Target Reaper cannot recover deleted data or provide atomic protection against hostile concurrent writers.

Each target scan captures one timestamp, one age cutoff, and one process snapshot covering visible executables, working directories, open files and mapped files. Linux uses /proc and openat2. macOS uses native lsof and mount capabilities plus descriptor-relative no-follow traversal, device/mount checks and descriptor path revalidation. macOS protects other processes working inside a project as well as identified Cargo workspace ancestors. Missing tools, warnings, incomplete snapshots and ambiguous native path output fail closed; macOS retries incomplete process snapshots at most three times. Its directory reads may update access times because macOS lacks Linux’s per-open O_NOATIME. Native path bytes and kernel-escaped map paths are preserved. Preview and execution apply these activity guards; execution takes a fresh snapshot before revalidating targets. A target is stale iff its strict scan observes no regular file under that target with mtime >= cutoff.

The age cutoff stays fixed throughout a pass. Metadata newer than the scan start is checked against the time it is observed: ordinary writes during a scan are fresh, not clock skew. Genuinely future-dated metadata still fails closed.

The library's scan_roots result carries this boundary in ScanResult.cutoff. Both delete_stale and delete_stale_with_config preserve it while refreshing process and mount activity. A later configuration may tighten the age boundary but cannot advance it. Library callers constructing ScanResult directly must supply the cutoff used to authorize staleness.

Traversal errors are not swallowed. Errors are recorded in the scan result and the CLI exits with code 3. By default, independently proven-stale targets may still be deleted when --execute is used. Add --require-clean-scan when you want the stronger policy: any target scan/classification error prevents target deletion. Cache and worktree cleanup use their own conservative checks and report command or traversal failures.

Git discovery permits at most 10,000,000 raw filesystem entries and 2,000,000 directory checks per root, with depth 128. Ordinary files consume the raw budget but not the directory-check budget. Cache/worktree measurement is limited to 256 levels and 2,000,000 entries; Cargo discovery and target scans to 256 levels and 10,000,000 entries. Per-file plans cap entries at 10,000,000 and directories at 1,000,000. Library walkers cap open directories at 16 each. Discovery-budget failures identify the offending path; exhausted limits fail closed rather than silently authorizing an incomplete tree. Sorted walkers can buffer wide directories, so these are not strict heap-memory guarantees.

Cache and Worktree Rules

  • Cache cleanup examines only immediate child directories of each explicitly supplied --cache-root. It keeps protected personal/model/Steam paths, non-owned data, symlinks, recent trees, and trees referenced by a visible process. On Linux, individual /proc entries that cannot be inspected are ignored; if /proc itself is unavailable, cleanup fails closed. On macOS, unavailable or incomplete native process/mount capabilities retain candidates. Process visibility is best-effort and can change after the check.
  • Worktree cleanup accepts --worktree-repo, --worktree-root, or both. Discovery does not follow symlinks or enter Git/JJ metadata or build payloads. Repositories are deduplicated by their canonical common Git directory; supplying a linked checkout never changes which registration is primary. Protected primary or shared-metadata namespaces retain the repository's worktrees, including registrations outside discovery roots.
  • Discovery prunes conventional SDK/package directories (.cargo, .rustup, node_modules, .venv, venv, __pycache__, CMakeFiles) and recognized Cargo output payloads. A verified native Git root overrides a generated directory name; an empty or bogus .git marker does not. Custom output is recognized by a regular .rustc_info.json or a .fingerprint directory plus a regular Cargo lock marker. Cargo.toml and .jj markers prevent structural output classification. Hidden directories, .cache, and .codex are not blanket-excluded; unrecognized payloads remain subject to the explicit traversal limits.
  • Integration uses verified main or master, never a feature-named origin/HEAD. With --refresh-worktree-defaults, origin is checked online. Preview retains a repository as needs_fetch when local proof is unavailable; execution fetches only the selected tracking ref with an empty refmap, without --force, tags, submodules, maintenance or FETCH_HEAD replacement. Offline, changed or unverifiable bases are retained. An absent cached origin/HEAD permits normal local fallback. An explicitly untrusted cached target or invalid/unsupported remote advertisement retains only that repository without blocking unrelated repositories; unexpected native-invocation and I/O errors still propagate.
  • Under the default integrated-only policy, primary, locked, JJ, bare, unborn, protected, recently modified, dirty, unmerged, or process-referenced worktrees are kept. A detached worktree is eligible only when its committed HEAD is an ancestor of the verified integration base. Missing registrations require the separate opt-in below.
  • Under that default policy, untracked or ignored files normally keep a worktree, including Cargo target/ directories, and artifact cleanup runs first. --allow-generated-worktree-cache permits only ignored .moon/cache/ with a valid CACHEDIR.TAG plus inert tools/build-toolchain.json identifying that exact checkout and the expected tool fingerprint. Unknown ignored data stays protected. A symlink's own timestamp contributes to activity checks; its target is not followed or counted.
  • Default cleanup refreshes Git identity, registration and HEAD before native git worktree remove without --force; source repositories and JJ stores are not purged.
  • Default cleanup also verifies the linked checkout's private Git directory. Absolute and relative native Git backpointers are resolved exactly, without traversing symlinks or interpreting a parent traversal through a missing prefix. Recent or process-referenced metadata, unintegrated recovery revisions, hidden index state, unknown files and unverifiable pointers retain the checkout. A fresh complete private snapshot must match the authorization immediately before removal.
  • Preview and execution both check visible activity. Execution repeats eligibility checks; process activity can change after any check.
  • The default policy retains worktrees with assume-unchanged or skip-worktree index entries, which can hide uncommitted changes. It reads native git ls-files -v -z output and never rewrites those flags. Explicit discard authorization permits loss of these hidden changes.
  • --execute applies to every explicitly enabled policy. Without it, targets, caches, files, worktrees, registrations and branches are preview-only.
  • Documents, Downloads, Steam, model directories, evidence, backups, snapshots, and project var/ trees are protected during root scans.

Whole-directory deletion uses safe recursive deletion (remove_dir_all). Per-file pruning uses descriptor-relative filesystem operations and revalidates entries before unlinking them.

Age-Authorized Workspace Discard

--discard-stale-workspaces --age-days 1 requires every observed file, directory and symlink in the checkout, private Git metadata and local JJ metadata to have mtime strictly older than one fixed 24-hour cutoff. Commit dates and access times do not authorize removal. Directory timestamps count, so recent deletions or renames keep a checkout. Fresh snapshots include inode, device, mode and change time to detect intervening mutations.

Discard runs before target/cache/per-file cleanup so its own artifact deletion cannot make an otherwise old checkout appear newly active. Target roots are validated before any discard; an explicitly supplied target root removed by that authorized pass is consumed rather than reported as an invalid root afterward.

Physical ownership, activity, protection and age rejection runs before expensive JJ lease preparation. These rejection reasons take precedence over JJ classification. Eligible removals still repeat the complete activity snapshot and fresh JJ alias/membership checks immediately before mutation; this ordering does not cache away the final safety checks.

Planning refreshes known JJ markers and relevant native store memberships without repeating the whole-scope alias walk for each candidate. Before every actual removal, the final guard still repeats scoped alias discovery for metadata-owning candidates. A new alias appearing after initial discovery may therefore change a preview candidate into retained execution state.

Primary Git/JJ roots, nested or shared stores, metadata owners referenced by another workspace, protected personal/model/excluded paths, foreign ownership, mounts and visible process references keep a checkout. Discovery does not follow symlink roots. Scoped JJ aliases and native memberships are verified again before removal; unknown or unsupported identity/registry state is retained. Protections cannot discover arbitrary aliases outside the supplied scopes.

Ordinary Rust src/model and src/models module directories do not count as model-weight collections merely because of their name. Only directories and regular .rs files qualify for this source-module classification; non-source payloads such as weights.bin, symlinks and other protected prefix/suffix namespaces still retain the whole checkout. Protected checkout-root namespaces are unchanged.

Present locked Git worktrees may be removed using native double-force removal only after all discard guards pass. Missing locked registrations are retained. Missing Git registrations still require --prune-missing-worktrees, an old verified private directory and fresh absence/identity/activity checks.

True JJ workspaces use native JSON names and commit IDs, verified store ownership, and an exact snapshot of the authoritative workspace registry. The physical checkout is removed first, then its exact native workspace name is forgotten only after revalidating surviving membership and the registry. If that second step fails, the command exits nonzero and explicitly reports that physical deletion already happened; it does not pretend the operation was rolled back. Preview does not create missing legacy registry files.

After a physical-removal/forget failure, fix the underlying lock or repository problem and use native exact-name jj workspace forget from the surviving anchor when required. Rerunning the cleaner alone does not automatically repair missing JJ registrations.

These are bounded, fail-closed checks, not atomic protection against hostile concurrent writers or a promise that unfinished work is recoverable. No service is stopped. Branch deletion remains a separate, merged-only policy even when workspace discard is enabled.

Merged Branches and Missing Registrations

--prune-merged-branches requires both a worktree scope and --refresh-worktree-defaults. Only branch tips strictly older than the fixed cutoff and integrated into the pinned main/master are eligible. Defaults, checked-out branches, and commits/parents owned by any scoped JJ workspace are protected. Every scoped repository's current worktree membership is refreshed before application; unreadable JJ state retains branches.

Ordinary Git branches use git branch -d, never forced deletion. The verified main/master may temporarily become the branch-specific upstream; failed or retained deletion restores the original tracking values. JJ primaries use exact-name jj bookmark forget, not bookmark deletion or push, so this does not schedule remote deletion.

Under the default policy, --prune-missing-worktrees uses selective native removal, never blanket git worktree prune. It requires an old, trustworthy private Git directory, integrated HEAD and HEAD reflog revisions, and no staged index differences. Optional ORIG_HEAD must name an actual integrated commit, not a tag or other object. An empty native refs directory is allowed; any contained private refs, unknown files, unique recovery state, or changed registration/index/reflog/absence retain the registration. The full private snapshot is checked again before removal. Discard mode changes recovery authorization, not primary/store/age/identity/activity protections.

Reports separate physical Git worktrees, JJ workspaces and their logical bytes from missing registrations and branch counts. --log includes workspace_policy=integrated-only or workspace_policy=discard-stale, numeric worktrees_*, jj_workspaces_*, stale_worktrees_* and branches_* counters, and fixed category-specific *_retained_REASON counters, including zero values. Reasons remain available with --quiet.

Ordering and decisions are deterministic for the same mode, configuration and filesystem/Git/JJ/process/remote snapshot. Preview is not a saved execution plan and does not simulate earlier removals: execution can release a branch by first removing its eligible worktree. Native commands have a 60-second timeout plus a 5-second kill grace. Captured output is rejected above 64 MiB after capture; this is not a peak-memory guarantee. Visible-process checks and final metadata revalidation do not make hostile concurrent mutations atomic.

Preview does not simulate whole-checkout removal: a nested old target can appear in both target and worktree estimates. Do not sum overlapping preview category bytes. Execution counts the actual removal once; an unchanged replay removes nothing further.

Explicit Per-File Pruning

--prune-root captures one cutoff at the start of its pruning pass. Only files with mtime < cutoff are eligible; directory timestamps do not make their old contents fresh. Roots and directory entries are ordered deterministically, and duplicate/overlapping roots are counted once. The listing is a preview, not a saved deletion plan: execution rechecks the filesystem and can retain changed or busy roots.

The mode keeps the protections for personal files, Steam, models, source checkouts, excluded paths, foreign ownership, and mounted filesystems. It refuses symlink roots and never follows symlink entries into their targets. Explicit roots may contain offline evidence, receipts, and backups that broad scans otherwise preserve.

Any detected executable, working directory, open file, or mapped file under a pruning root keeps the entire root, including its old files. This avoids deleting an old database segment while its owner is still running. No service is stopped. Process visibility is best-effort; inaccessible process details and a process starting after a check remain limitations.

Execution can temporarily grant owner-write permission to owned read-only directories, restoring their original permissions when retained. Dry-run does not change permissions. Empty directories are removed after their eligible files; missing roots are harmless on subsequent runs. Summary/log byte counts are logical file lengths, not physical space reclaimed.

Deletion or permission-restoration failures stop pruning and return a nonzero exit status; they are not reported as successful cleanup. Concurrent hostile writers remain a limitation: the final metadata check and unlink cannot be one atomic conditional operation.

Automatic Cargo Artifact Pruning

--prune-target-files is narrower authorization than --prune-root: only discovered Cargo targets qualify, and only recognized generated compiler outputs may be removed. It uses the same strict file cutoff, descriptor-relative deletion, exclusions, ownership/mount checks, activity checks and failure reporting as explicit pruning.

Recent files, nested source projects, corpus/evidence/receipt/backup directories, and database-bearing fixture subtrees are retained. Database markers protect their entire subtree, including journal/manifest/lock/keyspace files and SQLite sidecars, rather than merely preserving selected extensions. Automatic pruning does not remove empty directories, so retained fixture directory metadata is not discarded.

Without this flag, no new per-file cleanup occurs: whole targets containing recent or protected data remain intact. A completely old, safe target can still be removed as a whole; mixed-age or durable-data-bearing targets use the narrower per-file policy when requested.

Dry-Run vs Execute

Mode Flag Behavior
Dry-run (default) (none) Prints cleanup summaries. Nothing is deleted.
Dry-run list --list Prints stale paths plus the summary. Nothing is deleted.
Execute -e / --execute Removes eligible directories and explicitly authorized old files, then prints summaries.
Execute list -e --list Prints deleted paths plus the summary.

Dry-run is the default because accidentally deleting active build caches is expensive.
