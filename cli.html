Use Target Reaper / Documentation

CLI reference

Flags, defaults and exit codes for the current development version. For executable help, run target-reaper --help.

Flags

Flag Short Argument Default Description
--root -r DIR (repeatable) none Root directories to scan for Cargo targets. Repeat for multiple roots.
--cache-root — DIR (repeatable) none Inspect immediate child directories as cache entries. Set roots such as ~/.cache or /cache explicitly.
--prune-root — DIR (repeatable) none Explicitly authorize per-file age cleanup inside a specific directory. Recent files, excluded paths, and busy roots are retained. Missing roots are skipped.
--artifact-root — DIR (repeatable) none Discover generated fuzz/{corpus,artifacts,crashes,coverage,target}, mutants.out, and .cargo/mutants trees beneath this directory. Contents must be strictly older than 24 hours, even when --age-days 0.
--prune-target-files — — false Reclaim old generated compiler artifacts in discovered Cargo targets, including mixed-age targets. Requires --root; preserves source and durable fixture/database/evidence subtrees.
--worktree-repo — REPO (repeatable) none Inspect worktrees registered to this Git repository. Default policy requires clean, integrated work; primary repositories are always retained.
--worktree-root — DIR (repeatable) none Discover Git repositories recursively and inspect their registered worktrees. Discard mode also discovers JJ workspaces. Overlapping routes are deduplicated.
--discard-stale-workspaces — — false Authorize deletion of inactive old Git/JJ checkouts despite dirty, untracked, ignored, unmerged or recovery-bearing contents. Requires a worktree scope; preserves primary repositories and shared stores.
--prune-merged-branches — — false Remove old integrated local Git branches or forget matching local JJ bookmarks. Requires a worktree scope and --refresh-worktree-defaults; never deletes remote refs.
--prune-missing-worktrees — — false Remove old missing registrations after validating private metadata. Default policy also requires integrated recovery state; discard mode authorizes its loss. Locked missing registrations remain protected. Requires a worktree scope.
--allow-generated-worktree-cache — — false Permit only verified ignored Moon cache/toolchain outputs in otherwise eligible worktrees. Requires a worktree scope.
--refresh-worktree-defaults — — false Verify authoritative origin main/master. Execution may fetch the selected tracking ref; preview never fetches. Requires a worktree scope.
--worktree-min-size — SIZE 0 Independent minimum size for physical worktrees. Branches and missing registrations have no byte threshold.
--exclude — DIR (repeatable) protected-path defaults Additional paths excluded from target, cache, worktree, and per-file cleanup.
--age-days -a DAYS 1 Minimum age in 24-hour periods. Whole targets/caches are retained if recent; pruning evaluates each file independently.
--min-size -m SIZE 10MB Minimum size for whole targets/cache directories. Accepts 100M, 1.5GB, 2TB, 500K, 1048576 (raw bytes). Worktrees use --worktree-min-size; per-file pruning does not use either threshold.
--execute -e — false Actually delete. Without this, runs in dry-run mode.
--verbose -v — false Print every scanned target with its classification.
--list — — false Print stale target paths. Dry-run and execute default to summary-only output.
--quiet — — false Suppress optional per-target output. Prints only the final summary.
--jobs — N 2x CPUs, capped at 32 Classification worker threads; maximum 128. Useful for I/O-bound metadata scans.
--delete-jobs — N --jobs Safe recursive deletion Rayon threads; maximum 128.
--queue — N 4096 Bounded pipeline queue capacity; maximum 65536.
--cargo-only — bool true Only include Cargo project targets. Use --cargo-only=false for every directory named target.
--require-clean-scan — — false A target scan/classification error prevents target deletion. Other cleanup categories use their own checks.
--skip-fuzz — bool true Skip fuzz/target/ directories. Use --skip-fuzz=false to include them.
--log — PATH none Append numeric cleanup counters and retained reasons, plus the string workspace_policy, after completion. Creates parent directories automatically.
--lock-path — PATH Linux: /run/user/{uid}/target-reaper.lock; macOS: /private/tmp/target-reaper-{uid}.lock Override the shared advisory lock path. Use the same path for automation and manual invocations.
--help -h — — Print help (short form) with examples.
--version -V — — Print version.

Exit Codes

Code Meaning
0 Success — no errors during scan or deletion
1 Generic error — bad root path, I/O failure, deletion failure
2 Lock held — another target-reaper is running, or bad CLI arguments
3 Errors during classification — some targets could not be evaluated

Size Format

The --min-size flag accepts human-readable sizes. All values are case-insensitive.

Input Bytes
500, 500B, 500b 500
10K, 10KB 10,240
100M, 100MB 104,857,600
1.5G, 1.5GB 1,610,612,736
2T, 2TB 2,199,023,255,552
1048576 1,048,576 (raw bytes)
0.5MB 524,288 (fractional)

Arg Inference

Long flags can be abbreviated to their shortest unambiguous prefix:

target-reaper -r ~/src --exec     # → --execute
target-reaper -r ~/src --age 7    # → --age-days
target-reaper -r ~/src --min 10M  # → --min-size

Lock paths

The lock serializes cooperating runs. Use one consistent --lock-path for manual and scheduled runs. A dry run still acquires this operational lock.
